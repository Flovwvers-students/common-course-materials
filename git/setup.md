# Настройка Git и GitHub

Эта инструкция подходит студентам C++ и Java. Git хранит историю изменений на компьютере, GitHub хранит репозитории и позволяет обсуждать изменения. GitHub CLI (`gh`) помогает войти в GitHub и создавать запросы на проверку.

## 1. Аккаунт и программы

1. Создайте аккаунт на [GitHub](https://github.com/) и подтвердите почту. Если аккаунт уже есть, используйте его. Сообщите преподавателю свой **логин**, а не пароль или токен.
2. Примите приглашение в свой учебный репозиторий. Вход в аккаунт сам по себе не предоставляет доступ к нему.
3. На личном компьютере установите [Git](https://git-scm.com/install/) и [GitHub CLI](https://github.com/cli/cli#installation) для своей системы. На университетском компьютере используйте предустановленные программы; если чего-то нет, обратитесь к преподавателю или администратору.
4. Откройте новый терминал: PowerShell или CMD в Windows, Terminal в macOS или Linux. Проверьте:

```sh
git --version
gh --version
```

Если команда не найдена, проверьте установку и перезапустите терминал. Компилятор и среду разработки устанавливайте по материалам своего курса.

## 2. Университетский компьютер

Храните проекты, включая папку `.git`, на личном сохраняемом диске в папке `github`, а не на рабочем столе или в Downloads. Буква диска может отличаться; уточните её у преподавателя. Настройки профиля и вход могут сбрасываться между сессиями. В новом терминале проверьте доступ к файлам и вход в GitHub; при необходимости повторите настройку.

На общем компьютере задавайте имя и почту **внутри своего репозитория**, как показано ниже, чтобы не использовать чужую идентификацию. Не сохраняйте токены и пароли в проектах.

## 3. Проверка сети и прокси

Сначала проверьте доступ к публичному репозиторию:

```sh
git ls-remote --heads https://github.com/git/git.git
```

Если выводятся ветки, прокси настраивать не нужно. Если соединение не работает в сети университета, уточните настройки у преподавателя или администратора. В имеющейся методичке указан `proxy.kubsu.ru:8080` для сети университета. Проверить его можно одной командой:

```sh
git -c http.proxy="http://proxy.kubsu.ru:8080" ls-remote --heads https://github.com/git/git.git
```

Если проверка успешна и прокси необходим, для текущего терминала задайте переменные. Они могут влиять и на другие программы, поэтому закройте терминал после работы или удалите только добавленные вами значения.

PowerShell:

```powershell
$env:HTTP_PROXY = 'http://proxy.kubsu.ru:8080'
$env:HTTPS_PROXY = 'http://proxy.kubsu.ru:8080'
```

CMD:

```bat
set "HTTP_PROXY=http://proxy.kubsu.ru:8080"
set "HTTPS_PROXY=http://proxy.kubsu.ru:8080"
```

Linux/macOS (bash или zsh):

```sh
export HTTP_PROXY='http://proxy.kubsu.ru:8080'
export HTTPS_PROXY='http://proxy.kubsu.ru:8080'
```

Для доступа через прокси выполняйте команды Git и `gh` из этого же терминала. Дома сначала проверьте прямое соединение: университетский прокси там обычно не нужен. Адрес PAC-файла не является адресом прокси. При ошибке сертификата обратитесь к администратору; не отключайте проверку TLS. Не записывайте пароли в команды или URL. Подробная [диагностика прокси](https://github.com/Flovwvers-students/java-course-materials/blob/main/git/github-java-m3-setup.md#3-если-git-не-подключается-windows-10-и-прокси) сохранена в методичке Java.

## 4. Вход в GitHub

Выполните в терминале:

```sh
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
gh auth status --hostname github.com
```

Следуйте подсказкам: откройте предложенный адрес, введите показанный одноразовый код и подтвердите вход в **свой** аккаунт. В последней команде убедитесь, что указан ваш логин. `gh auth setup-git` позволяет Git использовать вход GitHub CLI при работе по HTTPS. Пароль GitHub для Git по HTTPS не подходит. Не публикуйте код входа, токен или пароль.

## 5. Клонирование и имя автора

На странице **своего** репозитория скопируйте HTTPS-адрес через кнопку Code. В терминале перейдите в папку для проектов и выполните, подставив адрес и имя своего репозитория:

```sh
git clone https://github.com/Flovwvers-students/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
git config user.name "Имя Фамилия"
git config user.email "ваша-почта@example.com"
git config --get user.name
git config --get user.email
```

Укажите свои данные без кавычек внутри значения. Для связи коммитов с профилем используйте подтверждённый в GitHub адрес или свой GitHub noreply-адрес из настроек почты. Эти настройки действуют только в текущем репозитории и влияют на будущие коммиты. `git clone` обычно выполняется один раз: если папка уже существует, откройте её, а не клонируйте поверх неё.

Если появляется `Repository not found`, проверьте адрес, вход в нужный аккаунт и принятое приглашение; не выкладывайте скриншоты с секретами. При затруднениях отправьте преподавателю текст ошибки без паролей, токенов и кодов входа.
